# Yobsidian 설계 문서

개인 전용 옵시디언 대체 앱. 웹, 윈도우, 맥에서 같은 화면을 쓰고, 노트는 구글 드라이브로 동기화한다.
기존 옵시디언 볼트를 그대로 열 수 있고, Yobsidian이 만진 볼트도 옵시디언에서 그대로 열려야 한다.

## 1. 목표와 범위

| 목표 | 기준 |
| --- | --- |
| 옵시디언 호환 | 볼트 = 평범한 폴더 + `.md` 파일. `[[위키링크]]`, `[[노트\|별칭]]`, `[[노트#제목]]`, `![[임베드]]`, `#태그`, YAML 프런트매터를 옵시디언과 같은 규칙으로 해석. `.obsidian/` 폴더는 읽기만 하고 절대 쓰지 않음 |
| 어디서나 | 웹(브라우저), 윈도우, 맥. 화면 코드는 하나 |
| 동기화 | 구글 드라이브의 한 폴더를 볼트로 쓰고 양방향 동기화. 오프라인에서도 편집 가능 |
| 개인 전용 | 사용자 1명. 계정·공유·협업 기능 없음. 라이선스 제약 고려 안 함 |

범위 밖: 옵시디언 커뮤니티 플러그인 실행, 실시간 공동 편집, 모바일 앱(구조상 나중에 Tauri 모바일로 확장 가능).

## 2. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 데스크톱 셸 | **Tauri 2** (Rust) | 윈도우 WebView2, 맥 WKWebView를 써서 설치 파일이 작음(수 MB). 로컬 파일 접근·감시를 Rust로 처리 |
| 화면 | **React 19 + TypeScript + Vite** | 웹 빌드와 데스크톱이 같은 번들을 씀 |
| 편집기 | **CodeMirror 6** (2단계) | 옵시디언도 CM6 기반. 라이브 프리뷰를 데코레이션으로 구현 가능 |
| 마크다운 해석 | `@lezer/markdown`(편집기) + `remark`/`unified`(인덱싱·읽기 모드) | 위키링크·태그·임베드는 확장 문법으로 추가 |
| 그래프 | 직접 만든 Barnes-Hut 포스 레이아웃 + Canvas 2D (외부 라이브러리 없음) | 노트 4000개에서도 틱당 약 16ms. 번들 크기를 늘리지 않고 웹/데스크톱 동작이 같음 |
| 로컬 캐시(웹) | IndexedDB | 오프라인 편집, 빠른 시작 |
| 동기화 | Google Drive API v3 (REST, `fetch` 직접 호출) | 웹과 데스크톱이 같은 코드 사용 |
| 테스트 | Vitest | Vite와 설정 공유 |

## 3. 전체 구조

```
┌──────────────────────── React UI (src/app, src/features) ────────────────────────┐
│  파일 탐색기 · 편집기(CM6) · 백링크 · 태그 · 그래프 · 검색 · 설정                       │
└───────────────┬─────────────────────────────────────────────┬────────────────────┘
                │ VaultAdapter (읽기/쓰기/감시)                  │ 인덱스 조회
┌───────────────▼──────────────┐                 ┌────────────▼───────────────────┐
│ 로컬 볼트 (항상 여기서 작업)    │◀── 변경 이벤트 ──│ 메타데이터 인덱스 (src/core/index) │
│  데스크톱: FsAdapter (Tauri)  │                 │  링크·백링크·태그·제목·별칭        │
│  웹:      IndexedDbAdapter   │                 └────────────────────────────────┘
└───────────────▲──────────────┘
                │ SyncEngine (src/core/sync)
┌───────────────▼──────────────┐
│ 원격: DriveAdapter (Drive v3) │
└──────────────────────────────┘
```

핵심 원칙 하나: **화면은 언제나 로컬 볼트만 읽고 쓴다.** 드라이브는 백그라운드 동기화 대상일 뿐이다.
그래서 오프라인에서도 똑같이 동작하고, 데스크톱에서는 로컬 폴더를 진짜 옵시디언으로 열어도 된다.

- 데스크톱: 로컬 볼트 = 사용자가 고른 디스크 폴더(FsAdapter). 드라이브 동기화는 선택.
- 웹: 로컬 볼트 = 브라우저 IndexedDB(IndexedDbAdapter). 드라이브가 원본이고, IndexedDB는 캐시 겸 오프라인 저장소.

## 5. 저장소 인터페이스

`src/core/vault/types.ts`의 `VaultAdapter`가 모든 저장소의 공통 계약이다.

```ts
interface VaultAdapter {
  readonly id: string;
  readonly name: string;
  list(): Promise<VaultEntry[]>;              // 전체 파일·폴더 (재귀)
  stat(path): Promise<VaultEntry | null>;
  readText(path) / readBinary(path);
  writeText(path, text) / writeBinary(path, bytes);   // 상위 폴더 자동 생성
  mkdir(path);
  rename(from, to);                           // 대상이 있으면 실패
  remove(path);                               // 폴더는 재귀 삭제
  watch?(listener): Unsubscribe;              // 외부 변경 포함
}
```

규칙:
- 경로는 볼트 기준 상대 경로, `/` 구분, 앞뒤 슬래시 없음. 루트는 `""`. `..`로 볼트 밖을 가리키면 거부.
- 텍스트는 UTF-8. 줄바꿈은 파일에 있던 그대로 보존(옵시디언과 diff가 생기지 않도록).
- 점(.)으로 시작하는 폴더(`.obsidian`, `.trash`, `.git`)는 탐색기에서 숨김. `.obsidian`은 쓰지 않는다.
- `MemoryAdapter`가 기준 구현이고, 테스트(`memory-adapter.test.ts`)가 곧 계약 명세다. 다른 구현은 같은 테스트를 통과해야 한다.

## 6. 옵시디언 호환 규칙 (2단계에서 구현)

- 링크 해석: `[[이름]]`은 확장자 없는 파일명으로 찾고, 같은 이름이 여럿이면 가장 짧은 경로 우선(옵시디언 "최단 경로" 방식). `[[폴더/이름]]`처럼 경로가 있으면 그 경로로.
- 새 링크 형식과 첨부 폴더 위치는 `.obsidian/app.json`의 `newLinkFormat`, `attachmentFolderPath`를 읽어 따른다.
- 파일 이름 변경 시 볼트 전체의 링크를 갱신(옵시디언 "링크 자동 업데이트"와 같게).
- 태그: 본문 `#태그`, `#중첩/태그`, 프런트매터 `tags`.
- 프런트매터: `aliases`도 링크 대상으로 인정.

## 7. 구글 드라이브 동기화 (4단계, 구현됨)

설정 방법은 [GOOGLE_SETUP.md](GOOGLE_SETUP.md).

**인증**
- 웹: Google Identity Services 토큰 클라이언트. 한 시간짜리 액세스 토큰만 받고(갱신 토큰은 서버가 있어야 함), 만료되면 상태가 "다시 로그인 필요"가 되며 다음 클릭/키 입력(사용자 제스처) 때 팝업 없이 재발급을 시도한다.
- 데스크톱: OAuth 2.0 PKCE + 루프백 리디렉션(`http://127.0.0.1:<임의 포트>`). Rust가 한 번만 연결을 받아 `code`를 넘기고, 갱신 토큰은 OS 키체인에 저장한다. 구글 호출은 Tauri HTTP 플러그인으로 보내서 웹뷰의 CORS 제약을 받지 않는다.
- 클라이언트 ID(와 데스크톱의 보안 비밀)는 사용자가 만든 Google Cloud 프로젝트의 값을 `VITE_GOOGLE_CLIENT_ID` 환경 변수 또는 앱 안의 설정에서 받는다. 코드에 내장하지 않는다.
- 스코프: `drive` 전체. 기존 볼트 폴더를 열려면 필요하다(`drive.file`은 앱이 만든 파일만 보임). 프로젝트를 "테스트" 상태로 두면 갱신 토큰이 7일마다 만료된다.

**동기화 방식**
- 볼트 = 드라이브의 한 폴더. 화면은 항상 로컬 볼트(`VaultAdapter`)만 읽고 쓰고, 엔진이 백그라운드에서 맞춘다.
- 파일마다 기록: `{ path → driveId, 마지막 동기화 시점의 MD5(base), 그때의 로컬 size·mtime }`. 폴더는 `{ path → driveId }`. 노트(`.md`, `.txt`)는 병합용으로 base 텍스트도 따로 보관한다.
- 해시는 MD5를 쓴다. Drive가 `md5Checksum`을 주므로 로컬 파일과 내려받지 않고 비교할 수 있다. size·mtime이 같으면 다시 읽지 않는다.
- 원격 변경 감지: `changes.list` + `startPageToken`. 자기 업로드가 되돌아온 것(이름·위치·md5가 기록과 같음)은 무시하고, 동기화 대상 폴더에 새로 생기거나 기록된 파일이 바뀐/삭제된 변경이 있을 때만 폴더 트리를 다시 훑는다. 30분마다, 수동 "전체 다시 확인", 실행 중 문제가 있었을 때도 전체를 훑는다.
- 경로별 판정 (L=로컬, R=원격, B=기록):
  - B 없음: 한쪽에만 있으면 복사, 양쪽에 있고 내용이 같으면 연결만, 다르면 충돌.
  - 한쪽만 바뀜 → 그쪽으로. 양쪽이 같게 바뀜 → 연결만.
  - 양쪽이 다르게 바뀜 → 노트는 줄 단위 3-way 병합(`merge3`), 깨끗하게 안 되거나 바이너리면 충돌 파일. 로컬 버전이 원래 경로에 남아 드라이브에도 올라가고, 원격 버전은 `이름 (충돌 2026-10-06 1530).md`로 로컬과 드라이브 양쪽에 저장된다.
  - 삭제: 반대편이 그동안 안 바뀌었으면 전파(로컬 삭제는 드라이브 휴지통, 원격 삭제는 로컬 `.trash/`로 이동). 반대편이 수정됐으면 삭제 대신 수정본을 살린다.
  - 폴더 삭제는 안이 비었을 때만 전파한다.
- 안전장치: 파일을 쓰기 직전에 사용자가 그 사이 고치지 않았는지 다시 확인하고, 고쳤으면 건드리지 않고 다음 실행으로 미룬다. 한 번에 삭제가 20개 넘고 전체의 절반을 넘으면 멈추고 사용자에게 확인을 받는다. 첫 동기화에서는 삭제가 일어나지 않는다(기록이 없으므로 합집합).
- 제외: `.trash/`, `.git/`, `.obsidian/workspace*.json`, OS 잡파일, 구글 문서류(내용 없는 파일), 이름에 `/`가 들어간 파일.
- 알려진 한계: 이름 변경은 삭제+새로 만들기로 처리, 드라이브의 중복 이름은 먼저 만든 것만 사용, 웹은 한 시간마다 재연결, 대/소문자만 다른 이름은 윈도우·맥에서 충돌.
- 로컬 변경 감지: 데스크톱 폴더 볼트는 2.5초 폴링과 창 포커스, 웹 볼트는 어댑터 `watch` 이벤트. 편집 3초 뒤, 창 포커스·네트워크 복구 시, 1분마다 동기화를 돌리고 실패하면 최대 5분까지 간격을 늘려 재시도한다.

## 7.5 검색·속성·첨부·템플릿 (5단계)

- **전체 검색**: 인덱스가 노트마다 소문자 본문을 한 번만 만들어 두고, 쿼리는 `includes`만 돈다(5천 노트 × 150단어에서 쿼리당 수십 ms, 테스트로 고정). 모든 조건이 AND. `"문구"`, `-제외`, `path:`, `file:`, `tag:`(하위 태그 포함, `#태그`도 가능), `content:`. 결과는 파일 이름 일치 → 등장 횟수 순이고, 보이는 노트에 대해서만 일치한 줄과 강조 범위를 만든다. 결과를 누르면 그 줄로 이동.
- **속성**: `properties.ts`는 YAML 라이브러리로 통째로 다시 쓰지 않고 해당 키의 줄 범위만 교체·삭제·추가한다. 주석, 키 순서, 중첩 맵 같은 모르는 값은 그대로 남고(패널에는 읽기 전용으로 표시), 줄바꿈(CRLF)도 유지한다. 편집은 편집기 문서에 변경 구간만 적용하고 바로 저장하므로 자동 저장·동기화 경로가 같다.
- **첨부**: 붙여넣기·드롭한 파일은 `attachmentFolderPath`(`/`=최상위, `./하위`=노트 옆, 그 외 볼트 폴더) 또는 앱 설정의 폴더에 저장한다. 붙여넣은 이미지는 `Pasted image 20261006093000.png`처럼 옵시디언과 같은 이름. 이름이 겹치면 `이름 1.png`. 삽입은 이미지 `![[이름.png]]`, 그 외 `[[이름.pdf]]`.
- **일일 노트·템플릿**: 옵시디언의 `.obsidian/daily-notes.json`, `templates.json`을 읽어 기본값으로 쓰고 앱 설정이 있으면 그것이 우선한다(`.obsidian`은 쓰지 않는다). 템플릿 변수는 `{{title}}` `{{date}}` `{{time}}`, `{{date:형식}}` `{{time:형식}}`(Moment 표기: `YYYY MM DD ddd HH mm [글자]` 등, 요일·월 이름은 한국어).
- **설정**: 이 기기의 localStorage(`yobsidian.settings`)에 저장. 테마(시스템/밝게/어둡게), 편집기 글자 크기, 첨부·일일 노트·템플릿 폴더.
- **명령 팔레트**: `App.tsx`의 명령 목록을 `ListPicker`로 보여준다. 새 동작은 이 목록에 항목 하나를 더하면 된다.

## 8. 배포

- 웹: `npm run build`로 나온 정적 파일(`dist/`)을 GitHub Pages나 Cloudflare Pages에 올린다(`deploy-web.yml`, 저장소 변수 `DEPLOY_TARGET`으로 고름). 서버 불필요(드라이브 API를 브라우저가 직접 호출). 상대 경로 빌드라 하위 경로 배포도 된다. PWA: `manifest.webmanifest`와 빌드 때 생성되는 `sw.js`(전체 파일 사전 캐시, 같은 출처 GET만 처리)로 설치·오프라인을 지원한다. 데스크톱 셸에서는 서비스 워커를 등록하지 않는다.
- 윈도우: NSIS 설치 파일(`.exe`)과 `.msi`.
- 맥: `.dmg`. 서명·공증 없이 쓰므로 처음 한 번은 Finder에서 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)가 필요하다.
- CI(`.github/workflows/ci.yml`)가 PR마다 웹 빌드·테스트와 윈도우·맥 설치 파일 빌드를 돌리고, 결과물을 아티팩트로 올린다.
  `v*` 태그를 푸시하면 `release.yml`이 윈도우(exe·msi)와 맥(universal dmg)을 빌드해 GitHub Release에 붙인다. 자세한 절차와 서명 없는 앱 경고 해결은 [배포 가이드](DEPLOY.md). 자동 업데이트(Tauri updater)는 서명 키가 필요해서 아직 붙이지 않았다.
